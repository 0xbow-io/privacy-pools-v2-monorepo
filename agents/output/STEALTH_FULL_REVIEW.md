## Verdict

**Cryptographically and structurally sound; ship-ready on security.** Security audit found **no
Critical/High/Medium** (both prior-round Lows now fixed in code). Code-review/coherence **PASS** (the
`Announcement` contract lines up across all four layers — contract struct / SDK type / Zod / relayer
ABI). The user-flow matrix confirms M-2 is genuinely closed and the on-chain STLTH-18 binding is real
(and the binding is meaningful because `PayoutRouting.recipient` is itself proof-committed via
`context = keccak256(abi.encode(transactParams, noteData))`, `PoolVault.sol:145-147`).

**Two confirmed gaps worth closing for external audit** (both verified by hand):

| ID | Sev | Lens | Finding |
|---|---|---|---|
| **G-1** | Med | flow / SDK-comprehension | The stealth module and the relayed transport are **not wired**: `prepareStealthWithdrawal` emits a self-multicall `StealthWithdrawalBundle` (`announce.viewTag: number`), while `RelayerInteractor.relayWithAnnounce` consumes `StealthAnnouncementFields` (`metadata: Hex`). No production code bridges them (`StealthAnnouncementFields` has only type/schema refs). The atomic **relayed** stealth flow is only reachable by hand-assembly — the M-2 class. |
| **TG-1** | High | test-gap | The **canonical (`0x0001`) scheme has no external interop vector**. Its fixture (`test/fixtures/scopelift/v6-internal-vectors.json`) states it pins the recipe "against itself… Generated by an ad-hoc Node + @noble/curves harness"; external agreement is "INTEROP-CANONICAL-02 (deferred)". Canonical is the scheme standard ERC-5564 wallets scan, so a recipe drift would silently break discovery — the exact risk FluidKey's real `@fluidkey/stealth-account-kit` vectors guard, left unguarded for canonical. |

## Lower-severity findings

- **TG-G2 (Med, test):** FluidKey's 65-byte uncompressed `ephemeralPubKey` + `0xfffe` never crosses the schema→wire surface (all wire/real-proof tests use canonical/compressed). Add a `relayWithAnnounce` test that a 65-byte key survives to the POST body.
- **TG-G3 (Med/Low, test):** orchestrator-level `prepareStealthWithdrawal` scheme-mismatch guard untested (only the lower dispatch layer is).
- **CR-1 (Low, dead code):** `derive.ts:91-92` re-export four per-scheme helpers no module imports via `derive.js`. Delete.
- **CR-2 (Low, simplification):** `canonicalPublicKeyToEvmAddress` + `fluidKeyPublicKeyToEvmAddress` are byte-identical EVM-address derivation; collapse to one helper.
- **CR-3 / CO-1 (Low, docs):** `announce.ts:46` "65-byte uncompressed" comment ignores canonical's compressed key; `resolve.ts:26-35` still says "v5 supports the `raw` mode only" though `canonical` is implemented (M-2 left it half-migrated).
- **L-C (audit, informational):** `scanAnnouncement` throws (rather than returns `null`) on an off-curve/malformed `ephemeralPubKey` — the ECDH parse runs before the view-tag filter. The announcer is permissionlessly spammable, so a scanner should treat adversarial input as a non-match; optional internal try/catch → `null`.
- **flow-G2/G3 (Low):** no submit helper for the self-multicall bundle; no `st:eth:` meta-address string parser feeding the canonical resolver.

## Correctly out of scope (not defects)

Stealth × batch/yield composition (C-3); ENS/ERC-6538 resolution (STLTH-05, deferred). FluidKey
scanning requiring the spending key (STLTH-17) is an accepted interop trade-off.
