# Test-Gap Report — LiFi Swaps (PR #333)

- **Commit:** `7a0b764e` (branch `review/swaps-333`)
- **Scope:** `RelaySwaps.sol` contract + SDK swap sessions (withdraw-and-swap, reshield, swap-and-deposit) + relayer swap quote/relay endpoints
- **Method:** TEST_GAP_AGENT, with TEST-7 (no-mock-only) and TEST-8 (schema→wire) applied strictly, against `docs/tech-design/sdk/withdraw-and-swap.md`.

## Verdict

**Coverage is broad and, for the contract revert surface and the SDK relay-time field asserts, genuinely strong** — every `RelaySwaps` custom error has a revert test, and both swap sessions validate all 11 routing tuple fields at relay time with per-field tamper tests. **But there are real gaps**, two of them High/Medium-High: an entire user flow (`PoolSessionSwapDeposit` / swap-and-deposit) has **no test that ever executes its session methods** (unit file absent; the integration test hand-rolls the flow), and the `LiFiSwapQuoteProvider` **quote-building/parsing methods** (`getSwapQuote`, `getSwapAndDepositQuote`) have **no unit or fixture test** — only the whole provider is mocked in session tests, so the parse that the SDK's echo cross-check trusts is never exercised off-chain. The proof-binding property is tested against a faithful keccak-mirror of `PoolVault.sol:147`, **not** a real Groth16 proof; real proofs run only in `describe.skipIf(!PRIVATE_KEY || !hasCircuits)` integration tests excluded from the default PR gate.

The proof-binding tamper property, minOutput balance-delta (pass+revert), native/ERC20 paths, approval reset, and every named revert are covered. Do not let the gaps below overshadow that the revert-parity and routing-tuple-assert coverage is close to complete.

## Gaps (ranked)

### G1 — [High] `PoolSessionSwapDeposit` session methods never executed (TEST-7)
- **Path:** `packages/sdk/src/services/poolSessions/PoolSessionSwapDeposit.ts` — public methods `prepareSwapAndDeposit` (L70), `executeSwapAndDeposit` (L142), `swapAndDeposit` (L176). Maps to the **swap-and-deposit user flow** (swap external token → deposit into pool).
- **Finding:** There is **no** `PoolSessionSwapDeposit.test.ts` (confirmed: every sibling session has one; this one does not). The only place the flow appears end-to-end is `packages/swaps/test/mainnet-crosschain-relay-swaps-deposit-from-ethereum.integration.test.ts`, which **hand-rolls** it: it calls `lifiProvider.getSwapAndDepositQuote()` (L313) and `session.prepareDeposit()` (L279) directly and **never** calls `prepareSwapAndDeposit`/`executeSwapAndDeposit`/`swapAndDeposit`. So those three methods — including the allowance-management logic at L184-235 (`assertPreparedTxMatches`, spender check, `currentAllowance >= amount` short-circuit, native-asset branch) — run in **zero** tests, mock or real. This is the exact TEST-7 class: "a session method the mocked unit test drives but the e2e hand-rolls (so the method itself never runs for real)" — here it is worse, there is no unit test either.
- **Classification:** TEST-7 (no-mock-only; here no-coverage-at-all).
- **Add:** `packages/sdk/test/unit/services/PoolSessionSwapDeposit.test.ts` mirroring the Reshield test harness. Cover: `prepareSwapAndDeposit` happy path (asserts the LiFi `getSwapAndDepositQuote` echo cross-check on `fromToken/toToken/fromChainId/toChainId`, and that `pendingNote` deposit target is proof-bound correctly); `swapAndDeposit` approval flow — (a) ERC20 with `currentAllowance < amount` → emits approve to exactly `amount` on the validated spender, (b) `currentAllowance >= amount` → **skips** approve, (c) native asset → no approve, (d) `assertPreparedTxMatches`/spender-mismatch rejection at L194-202, (e) `executeSwapAndDeposit` when `approvalReceipt.status === false` → aborts before the swap tx. Assert `SwapQuoteMismatch` and the deposit-target/`AssetNotSupported`/`DepositBelowMinimum` errors from `errors/PoolSessionSwapDeposit.ts`.

### G2 — [Medium-High] `LiFiSwapQuoteProvider` quote-build/parse untested off-chain (TEST-7)
- **Path:** `packages/sdk/src/services/LiFiSwapQuoteProvider.ts` — `getSwapQuote` and `getSwapAndDepositQuote`. Maps to **all three swap flows** (every session consumes the parsed `transactionData`/`transactionTo`/`approvalAddress`/`toAmountMin`/echoed `fromToken/toToken/fromChainId/toChainId`).
- **Finding:** `LiFiSwapQuoteProvider.test.ts` tests **only `getSwapStatus`** (status polling via stubbed `fetch`). The quote-building methods — which construct the LiFi request and parse its response into the fields the SDK's `SwapQuoteMismatch` echo check and on-chain `swapTarget`/`approvalAddress` asserts depend on — have **no unit test**. Every session test injects a hand-built mock provider (`createMockSwapQuoteProvider` / `createMockSwapAndDepositQuoteProvider`), so the real parse never runs. Two real LiFi response fixtures already sit unused in the repo: `packages/swaps/test/full_swap_response.json` and `full_swap_and_contract_response.json`. The only real exercise of these methods is the `skipIf`-gated integration suite (G8) — excluded from the default PR gate. This is TEST-7: the behavior a mock silently gets wrong (a drifted LiFi field mapping — e.g. reading `estimate.toAmountMin` vs `transactionRequest.to`) is never caught, and a mismapping would defeat the echo cross-check that the whole "LiFi routed a different token/chain" defense rests on.
- **Classification:** TEST-7 (real counterpart is fixture-replay; currently only gated integration exists).
- **Add:** `getSwapQuote`/`getSwapAndDepositQuote` fixture-replay tests: stub `fetch` to return `full_swap_response.json` / `full_swap_and_contract_response.json`, assert the provider maps `transactionData`, `transactionTo`, `approvalAddress`, `toAmount`, `toAmountMin`, and echoes `fromTokenAddress/toTokenAddress/fromChainId/toChainId` exactly. Add a negative case: a fixture whose echoed `toToken` differs from the request → the provider surfaces the raw echo so the session's `SwapQuoteMismatch` fires (assert at the session boundary too).

### G3 — [Medium] Output-token dust sweep + delta-only parallel-safety untested (TEST-7)
- **Path:** `packages/swaps/contracts/src/RelaySwaps.sol` `_sweepDust` L357-363 (output-token branch) and the delta-only guards L345/L352/L360. Maps to withdraw-and-swap dust handling / **parallel-execution safety** invariant (the headline reason the sweep is delta-based).
- **Finding:** `RelaySwaps.t.sol` tests input-token dust (`test_SweepInputTokenDust`) and ETH dust (`test_SweepETHDust`) — but **not** output-token dust (the `_outputToken != NATIVE_ASSET && _outputToken != _inputToken` branch never fires with a nonzero delta; both dust mocks leave input/ETH dust only, output goes straight to `recipient`). Critically, **the delta-only property is never asserted**: both existing sweep tests start with the contract at a **zero** pre-balance, so `_ethBefore`/`_inputBefore` are 0 and `delta == fullBalance`. A regression that swept the full balance instead of the delta (`_ethNow` instead of `_ethNow - _ethBefore`) would **pass** every current test — yet that is exactly the drain-parallel-executions bug the delta design exists to prevent.
- **Classification:** TEST-7 (invariant asserted in comments/design only, never exercised).
- **Add:** (a) `test_SweepOutputTokenDust` — a swapper that mints surplus output token to the contract (not the recipient), assert only the surplus is swept to `dustRecipient`; (b) `test_DustSweepIsDeltaOnly_ETH` and `_ERC20` — **pre-seed** the contract with a stuck balance (e.g. from a prior parallel tx), run `execute`, assert the pre-seeded balance is **untouched** and only the new delta is swept. Mutation-check: change `- _ethBefore` to `0` and confirm the delta test fails.

### G4 — [Medium] Relayer `quoteSwap` field survival into committed blob not asserted (TEST-8)
- **Path:** `packages/relayer/.../quote/evm/evm.quote.service.ts` L281-392 (routing encode; `approvalAddress ?? swapTarget` default at L358). Tests: `evm.quote.service.spec.ts` "Commits a routing blob…" (L567, L584).
- **Finding:** The committed-blob tests decode the routing and assert `recipient`, `minOutputAmount`, `nativeGas`, `feeRecipient`, `fallbackAddress`, `feeAmount` survive — but **do not assert** `swapTarget`, `approvalAddress`, `outputToken`, `swapCalldata`, or `dustRecipient` reach the encoded tuple. `approvalAddress` is the highest-risk: it is **not even present in `baseSwapParams`**, so the `approvalAddress ?? swapTarget` default branch (L358) is untested and the explicit-`approvalAddress` branch is untested. This is the H3 field the on-chain allowlist now pins; if zod stripped it or the encoder dropped it, the signed routing would carry a wrong/zero `approvalAddress` and no relayer test would catch it. TEST-8 exactly: a field present on the request type but not proven to reach the wire (here the signed commitment blob).
- **Classification:** TEST-8 (schema→wire), with a TEST-5 error-path angle on the default branch.
- **Add:** Extend "Commits a routing blob with a nonzero recipient" to also assert `routing.swapTarget === TEST_SWAP_TARGET`, `routing.outputToken === TEST_OUTPUT_TOKEN`, `routing.swapCalldata === TEST_SWAP_CALLDATA`, `routing.dustRecipient === ...`. Add two cases: (a) request **with** explicit `approvalAddress` → `routing.approvalAddress` equals it; (b) request **omitting** `approvalAddress` → `routing.approvalAddress === swapTarget` (default branch).

### G5 — [Medium] Proof-binding proven only via keccak-mirror mock; tamper covers 2 of 11 fields; no real-Groth16 tamper (TEST-7 / TEST-3)
- **Path:** `packages/swaps/contracts/test/RelaySwapsProofBinding.t.sol`. Maps to the design doc's headline security property ("changing any byte of the LiFi calldata invalidates the ZK proof").
- **Finding:** `ContextBindingPool` faithfully re-implements `PoolVault.sol:147` (`context == keccak256(abi.encode(params, noteData)) % SNARK_SCALAR_FIELD`), and tamper tests exist for `swapCalldata`, `swapTarget`, and `noteData`. Two caveats: (1) it is a **mock mirror, not a real Groth16 proof** — the real verifier path (`MockVerifier` returns `true` in all non-gated tests) is never run in default CI, so per TEST-3 there is no real-proof tamper coverage in the PR gate; (2) only 2 of the 11 routing fields are individually tamper-tested. Because the context is a single hash over the whole struct, testing two fields demonstrates the *mechanism*, so this is lower-priority than G1-G4 — but the doc's claim is per-field, and a real-proof happy+tamper pair would close it.
- **Classification:** TEST-7 (mock-mirror stands in for real Groth16; real counterpart is gated-only) / TEST-3.
- **Add:** In the gated real-proof integration suite, add one **tamper** case (mutate a routing field after proving, submit, expect the pool's context revert) so at least one real-Groth16 tamper is observed. Optionally parametrize the mock tamper test over the remaining routing fields (feeAmount, dustRecipient, minOutputAmount, approvalAddress, outputToken, recipient) for completeness.

### G6 — [Low-Medium] `RelaySwaps` reentrancy guard untested
- **Path:** `RelaySwaps.sol` `execute` `nonReentrant` (L205). Router is allowlisted so exposure is reduced, but the guard is deliberate defense.
- **Finding:** No test drives a reentrant `swapTarget`. If the `nonReentrant` modifier were dropped, no test fails.
- **Classification:** TEST-5 (guard with no asserting test).
- **Add:** `test_RevertWhen_Reentered` — a malicious mock router (allowlisted) that calls back into `relaySwaps.execute` during the swap; assert the reentrancy revert.

### G7 — [Low] Same-chain relay-time `minOutputAmount` divergence not directly tamper-tested
- **Path:** `PoolSessionWithdrawAndSwap` relay-time routing assert (design doc L267). The **cross-chain** case (`minOutputAmount` must be 0) is tested; the **same-chain** "routing `minOutputAmount` must equal caller `minOutputAmount`" tamper is not a dedicated case.
- **Classification:** TEST-5.
- **Add:** `reject routing whose minOutputAmount differs from caller (same-chain)` in `PoolSessionWithdrawAndSwap.test.ts` routing-tuple describe.

### G8 — [Low, informational] Real swap proof path runs only in `skipIf`-gated integration (CI-selection)
- **Path:** all `packages/swaps/test/*swap*.integration.test.ts` guarded by `describe.skipIf(!PRIVATE_KEY || !hasCircuits ...)`. Real relay methods driven: `prepareSwapQuote`, `relayWithdrawAndSwap` (×3), `relayReshield` (×1). `estimateReshieldAmount` and `prepareReshieldQuote` are **not** driven by any real test — the reshield integration hand-rolls the quote via `getSwapAndDepositQuote` + `prepareDeposit`, so those two RPC-backed methods are **mock-only** (same pattern as the yield-withdraw finding in the agent doc's history). Default PR CI runs **no** real swap proof (MockVerifier returns true).
- **Classification:** TEST-4 (CI-selection) + TEST-7 (estimate/prepareReshieldQuote mock-only).
- **Add:** Note in CI docs that swap real-proof coverage is gated/unrun-in-PR. If feasible, drive `estimateReshieldAmount`/`prepareReshieldQuote` in the gated reshield integration instead of hand-rolling, so the RPC-backed budget/echo checks run against real Entrypoint state at least once.

## Informational (not test gaps)
- `RelaySwaps_InvalidCalldata` (`RelaySwaps.sol:103`) is **declared but never thrown** — dead code; belongs to code-review/alignment, not test-gap. No test can cover an unreachable revert.
- ERC20 approve **scope** amount (approve to exactly `_swapAmount`) is not asserted mid-swap; only the **reset to 0** is (`test_ApprovalResetAfterSwap`). Low value to add given the reset is the security-relevant half.

## LiFi provider non-mock coverage — explicit answer
The LiFi provider is inherently external/mocked. Its **quote-building methods have no non-mock (fixture/replay) counterpart** in the unit suite (G2) — the two real response fixtures in `packages/swaps/test/` are unused by any unit test. Its only real exercise is the `skipIf`-gated mainnet integration suite (G8), which is excluded from the default PR gate. `getSwapStatus` alone has thorough (mocked-`fetch`) coverage.
